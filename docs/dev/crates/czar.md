# czar

_Updated at: 2026-10-02_

The Rust SDK for writing czar tasks. Task crates depend on this one crate.

## Owns

- [`lib.rs`](../../../crates/czar/src/lib.rs): task input and output (`read_input`, `write_output`, `run_task`, `run_task_with_context`), `Context` (logs, metrics, progress), the C ABI entry points for the library executor (`czar_task_library!`), and `IntoTaskResult`, which lets a `#[task]` function return either `T` or `Result<T, E>`.
- [`wasm.rs`](../../../crates/czar/src/wasm.rs): the Wasm entry points (`czar_task_wasm!`).
- [`deferrables.rs`](../../../crates/czar/src/deferrables.rs): the Deferred job types a task returns to hand work to BigQuery, Dataproc, Cloud Run or an HTTP endpoint.
- Re-exports `#[task]` from [czar-macros](czar-macros.md).

## Notes

- Code generated by `#[task]` refers to `::czar::...` paths, so the macro only works through this crate.
- `czar-macros` is a separate crate only because Rust requires procedural macros to live in a crate of their own. Task code never names it.
